在长视频中找到关键时刻

我的研究始于一个宽泛的目标：让长视频问答更高效。我选择重新组织智能体使用的证据，再通过实验检验工作流中的哪些环节仍值得投入成本。

研究起点

一个小问题，可能需要漫长的搜索

有用的线索可能只出现一瞬间，而理解它却要联系更早或更晚发生的事件。只抽取少量视频帧，可能错过线索；输入更多帧，又会增加处理量和上下文需求。

面对开放的研究目标，我选择聚焦这一信息瓶颈：系统如何定位证据，并保留足够的上下文来理解它。这也关联到更广泛的智能体设计问题。规划、检索和复核都会消耗资源，而这些环节的价值，部分取决于它们接收到的信息。

我选择研究的问题能否在问题到来之前先组织好视频，从而减少回答每个问题所需的工作？

设计选择

从事件出发，循线找到细节

我借用了回忆中的一个简单直觉：先想起大致发生的事件，再沿着它找到具体细节。据此，我构建了一个无需训练的层次结构，包含事件摘要、更短时段的描述，以及指向原始视频帧的链接。

索引只需构建一次，就能供多个问题复用。回答时，智能体可以先通过概览定位相关内容，再查看底层视频帧。这样既将部分工作移至离线阶段，也保留了查阅摘要可能遗漏的细节的能力。

事件图谱只是一个设计假设。要判断它是否有效，我需要衡量整个回答过程中寻找和使用证据所需的工作。

我如何检验这个想法 采样、配对比较与输入消融实验

主要评估使用了 HourVideo 中 12 段长视频的 300 道视觉五选一问题。在资源有限的情况下，我按原始问题类型的分布比例进行采样，随后比较答案正确率、完成情况和记录的在线资源消耗。

不同研究问题需要不同的控制条件：我分别比较了改编后 VideoSEAL 工作流中的检索设置、在相同问题上使用的索引表示，以及在索引和模型保持不变时的 Direct 与 Staged 执行方式。离线构建和在线作答分别核算。

实验发现

更好的图谱，会改变工作量的分布

我改编了已有的视频问答系统 VideoSEAL，用于比较扁平检索和层次检索。其中一种层次检索设置，在观察到的准确率接近扁平检索的同时，减少了记录的处理开销。但在更大的检索预算下，这一优势消失了。因此，检索策略与作答工作流必须放在一起评估。

准确率以全部 300 道问题为分母，未完成的问题计为错误。用时为每道问题选定的一次最终尝试的记录时长之和，包含已记录的失败执行开销，不包含被后续尝试取代的执行记录和离线构建时间，因此不等于实际总耗时。这些比较同时改变了索引和检索流程；准确率接近，并不能证明两者在统计上等效。

索引比较还揭示了另一种权衡。更丰富的语义描述增加了规划器（Planner）需要处理的文本，却减少了规划之后的工作。在满足上下文容量限制的 150 道配对问题子集上，完整工作流的在线 token 用量下降了 27.2%，答对数量则从 51 道变为 52 道。

收益来自工作量的重新分配。规划阶段增加的投入，换来了后续处理量的减少。

更丰富的图谱也有局限。300 道问题中，有一半的语义索引输入超出了本地规划器的上下文容量。改用 API 规划器后，总 token 用量下降了，但规划器的 API 费用却上升了。

因此，我必须追踪整个流程：总 token 用量的节省，可能与某一个模型费用的上升同时发生。

R1 使用目标检测与跟踪；R3 使用语义图像描述。本地比较仅涵盖两种输入都满足上下文容量限制的 150 道问题。其准确率差异不显著，也不能据此认定两者等效。在独立的 API 规划器实验中，R3 的规划器费用为 $10.10，R1 为 $4.97；本地 GPU 成本未折算为金额。

重新审视工作流

有了图谱，还有多少阶段值得保留？

预先构建的索引，也让我能够重新检验执行结构。我比较了 Full Staged 工作流与 Direct 智能体；后者可以查阅图谱，并按需查看视频帧。

Staged
将规划、证据调查、可选的视频帧复核和最终作答分为独立阶段。
Direct
由一个作答智能体使用图谱，并按需查看原始视频帧。

在相同的 100 道问题上，使用相同的语义索引和模型，Direct 的在线 API 支出降低了 70.3%。它答对了 32 道问题，Full Staged 答对了 24 道，不过准确率差异未达到统计显著水平。

在这一配置下，额外阶段未表现出足以支持其额外成本的准确率收益。这一结果支持在所测试的任务中采用更简洁的工作流。

检验证据究竟能支持什么

图谱也影响答案能作出哪些判断

一项独立的视频与语音案例研究揭示了另一种局限。语音补充了协调行动和医疗处置的背景，改变了事件图谱，以及部分查看视频帧的选择。然而，语音中提到治疗，并不能证明画面中实际展示了治疗过程。

这影响了我对输出的解读：答案是否正确、获得了哪些背景信息，以及是否有直接的视觉证据支持，需要分别考察。

研究收获

更好的信息，能让更简洁的智能体成为可行选择

索引的价值，取决于作答系统如何使用它。有些配置减少了在线工作量；另一些则遇到了上下文容量限制，或将成本转移到了其他阶段。在配对工作流比较中，更简洁的智能体是更经济的选择。

这项研究让我形成了一条设计原则：先判断哪些信息可以预先准备并复用，再检验每一个额外执行阶段带来的效果改善，是否足以支持其成本。

从一个宽泛的目标出发，我将研究问题落实为索引系统、不同的作答工作流和受控比较，由此形成了一种具体方法，用来考察证据组织方式与智能体复杂度之间的关系。
