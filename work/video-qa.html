Finding the right moments in a long video

I began with a broad goal: make long-video question answering more efficient. My approach was to reorganize the evidence an Agent works with, then test which parts of its workflow were still worth the cost.

THE STARTING POINT

One small question can require a long search

A useful clue may appear for only a moment, while its meaning depends on events much earlier or later. Sampling a few frames can miss it. Sending more frames creates additional processing and context demands.

With an open research target, I chose to focus on that information bottleneck: how the system locates evidence and preserves enough context to interpret it. This connects to a wider Agent design problem. Planning, retrieval and review all consume resources, so their value depends partly on the information they receive.

The question I chose to investigateCould organizing a video before questions arrive reduce the work needed to answer each one?

THE DESIGN CHOICE

Start with an event, then follow it back to the detail

I borrowed a simple intuition from recollection: a broad event can provide a route back to specific details. I built a training-free hierarchy of event summaries, shorter descriptions and links to source frames.

The index is constructed once and reused across questions. At answering time, the Agent can use the overview to locate relevant content and inspect the underlying frames. This shifts some work offline, while keeping access to details the summary may have missed.

The map was a design hypothesis. To judge whether it helped, I needed to measure the work of finding and using evidence across the answering process.

How I tested the idea Sampling, paired comparisons and input ablations

The main evaluation used 300 visual, five-choice questions across 12 long videos from HourVideo. Under limited resources, I sampled questions in proportion to the source question-type distribution, then compared answer correctness, completion and recorded online resources.

Different questions required different controls: retrieval settings within an adapted VideoSEAL workflow, index representations on shared questions, and Direct versus Staged execution with the index and model held fixed. Offline construction and online answering were accounted for separately.

WHAT THE EXPERIMENTS REVEALED

A better map changes where the work happens

I adapted an existing video-QA system, VideoSEAL, to compare flat and hierarchical retrieval. One hierarchical setting kept observed accuracy close to flat retrieval while using less recorded processing. At a larger retrieval budget, that advantage disappeared. The retrieval strategy and the answering workflow had to be evaluated together.

The index comparison exposed another trade-off. Richer semantic descriptions gave the Planner more text to process, but reduced work after planning. On the context-feasible 150-question subset, full-workflow online tokens fell by 27.2%, with 52 rather than 51 correct answers.

The gain came from redistribution. More effort at the planning stage was offset by less downstream processing.

The richer map also had limits. Half of the 300 semantic-index inputs exceeded the local Planner's context capacity. With an API Planner, total tokens fell but the Planner's API bill increased.

I therefore had to follow the whole process: a saving in total tokens could coexist with a higher bill for one model.

R1 uses object detection and tracking; R3 uses semantic captions. The local comparison covers only the 150 questions admitted by both context limits. Its accuracy difference was not significant and does not establish equivalence. In the separate API Planner experiment, the Planner bill was $10.10 for R3 and $4.97 for R1; local GPU cost was not monetized.

QUESTIONING THE WORKFLOW

With the map in place, how many stages were still useful?

A prepared index also made it possible to question the execution structure. I compared a Full Staged workflow with a Direct Agent that could consult the map and inspect frames as needed.

Staged
Separate planning, evidence investigation, optional frame review and final answering stages.
Direct
One answering Agent uses the map and can inspect source frames as needed.

On the same 100 questions, using the same semantic index and model, Direct incurred 70.3% lower online API expenditure. It answered 32 questions correctly versus 24 for Full Staged, although the accuracy difference was not statistically significant.

For this configuration, the additional stages had no demonstrated accuracy gain to justify their extra cost. The result supported a simpler workflow for the tested task.

CHECKING WHAT THE EVIDENCE REALLY SUPPORTS

The map also shapes what an answer can claim

A separate video-and-speech case study exposed a different limit. Speech added context about coordination and medical response, changing the event map and some inspection choices. Yet a spoken reference to treatment did not establish that the treatment was visibly shown.

This mattered to how I interpreted the outputs: answer correctness, contextual information and direct visual support needed to be considered separately.

WHAT I TAKE FROM THIS WORK

Better information can make a simpler Agent viable

The value of the index depended on how the answering system used it. Some configurations reduced online work; others ran into context limits or moved cost to a different stage. The simpler Agent was the more economical choice in the paired workflow comparison.

The design principle I take from this is to ask what information can be prepared and reused, then test whether each additional execution stage improves the outcome enough to earn its cost.

Starting from a broad target, I turned that question into an indexing system, alternative answering workflows and controlled comparisons. The result is a concrete way to examine the relationship between evidence organization and Agent complexity.
